Task:
Create a concise daily summary using all provided conversation logs and wearable data.

Critical rules:
- Do NOT invent conversational details.
- Use the full messages list as the primary source for conversational findings.
- If conversation and wearable are both missing/invalid, return exactly:
  {"result":[{"category":"Summary","conversation_log_ids":"[]","content":"No valid conversation or wearable data available for today."}]}
- If data exists but there are no concerning abnormalities, return a reassuring summary such as:
  "Overall status appears stable today; continue routine monitoring."

Instructions:

Use all messages from the day, not only abnormal symptoms.
Incorporate wearable data when available (heart rate, respiration, HRV trends).
If symptoms are normal/denied and wearable looks stable, explicitly say the day is stable and keep monitoring.
Output Format: Present the summaries in an array of objects. Include the following properties:
category: "Summary"
conversation_log_ids: A string listing the log IDs used (e.g., "[1698, 1699]"), or "[]" when none.
content: A concise daily summary grounded in provided data.
Example of Summary Format:

{
    "result": [
        {
            "category": "Summary",
            "conversation_log_ids": "[1698, 1699]",
            "content": "Patient reports mild shortness of breath on exertion; wearable trends remain stable overall."
        },
        {
            "category": "Summary",
            "conversation_log_ids": "[]",
            "content": "Overall status appears stable today; continue routine monitoring."
        }
    ]
}
